# ระบบสั่งจองเสื้อที่ระลึก ผ้าป่าศิษย์เก่า 2569

สถาปัตยกรรม: **หน้าเว็บ single page (`index.html`) บน GitHub Pages** → เรียก **Apps Script Web App (`Code.gs`, JSON API)** → **Google Sheets + Drive**

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าบ้าน (สั่งซื้อ/ติดตาม/แนบสลิป) + หลังบ้านที่ `#admin` |
| `design.jpg` | รูปแบบเสื้อ ราคา ตารางไซส์ |
| `qr.jpg` | QR พร้อมเพย์ (สำรอง ถ้ายังไม่ได้อัปโหลดที่หลังบ้าน) |
| `Code.gs`, `appsscript.json` | Backend (วางใน Apps Script) |

## ติดตั้ง Backend
1. script.google.com → โปรเจกต์ใหม่ วาง `Code.gs` และ `appsscript.json` (เปิด Project Settings → Show appsscript.json)
2. รัน `setupSystem()` หนึ่งครั้ง → อนุญาตสิทธิ์ → ดูรหัสหลังบ้านใน Execution log (สร้าง Sheet + โฟลเดอร์ Drive ให้อัตโนมัติ)
3. Project Settings → Script properties: ตั้ง `ADMIN_PASSCODE`, `TEACHER_EMAIL` (ถ้าใช้ LINE: `LINE_TOKEN`, `LINE_TO`)
4. Deploy → New deployment → Web app → Execute as: **Me**, Who has access: **Anyone** → คัดลอก URL ที่ลงท้าย `/exec`
5. ทดสอบ: เปิด URL `/exec` ในเบราว์เซอร์ ต้องเห็น `{"ok":true,"service":"shirt-order-api",...}`

## ติดตั้งหน้าเว็บบน GitHub Pages
1. เปิด `index.html` แก้บรรทัด `const API_URL='PASTE_WEB_APP_URL_HERE';` เป็น URL จากข้อ 4
2. สร้าง repo → อัปโหลด `index.html`, `design.jpg`, `qr.jpg`, `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (+ `.gitignore`) — ไฟล์หลังสุด 4 ตัวทำให้ติดตั้งเป็นแอปได้
3. Settings → Pages → Branch: `main` / root → ได้ลิงก์ `https://<user>.github.io/<repo>/`
4. หลังบ้าน: `…/<repo>/#admin` → แท็บ QR อัปโหลดรูป QR (ถ้าต้องการเปลี่ยน)

## ความเป็นส่วนตัวของข้อมูลผู้สั่ง / ติดตามสถานะ / วิธีรับสินค้า
- **ติดตามสถานะ / แจ้งโอน / ใบสั่งซื้อ-ใบเสร็จ** ซ่อนไว้จนกว่าจะกดเมนู "ติดตาม" แล้วกรอกเลขที่ออเดอร์ + เบอร์โทร ผลจะแสดงเมื่อค้นหาเท่านั้น และถูกล้างเมื่อกด "✕ ปิด/ล้างข้อมูล" หรือไม่มีการใช้งาน 5 นาที (เหมาะกับเครื่องที่ใช้ร่วมกัน)
- **หลังสั่งซื้อสำเร็จ** ระบบล้างข้อมูลผู้สั่ง ที่อยู่ ไซส์ที่เลือก และผลการค้นหาออกจากหน้าจอทั้งหมด และ **ไม่จำข้อมูลลงเครื่องอีกต่อไป** (เวอร์ชันเก่าที่เคยจำชื่อ/เบอร์ไว้ จะถูกลบตอนเปิดหน้าเว็บ) · หน้าต่างสำเร็จมีปุ่ม "📎 แนบสลิปโอนเงิน" เปิดช่องค้นหาพร้อมเลขที่ออเดอร์ (ต้องพิมพ์เบอร์โทรเอง)
- **วิธีรับสินค้า** เป็นตัวเลือกแบบติ๊ก: รับที่โรงเรียน / จัดส่งไปรษณีย์ — เมื่อติ๊กจัดส่งไปรษณีย์ จะมีช่องชื่อผู้รับ เบอร์ผู้รับ ที่อยู่ ตำบล/แขวง อำเภอ/เขต จังหวัด รหัสไปรษณีย์ (5 หลัก) พร้อมคำอธิบายสั้น ๆ ใต้ช่อง ระบบตรวจความครบถ้วนทั้งฝั่งหน้าเว็บและฝั่งเซิร์ฟเวอร์ แล้วรวมเป็นที่อยู่ในใบสั่งซื้อ/ใบเสร็จ (เห็นเฉพาะผู้ดูแลและเจ้าของออเดอร์)

## ตรวจสลิปโอนเงินอัตโนมัติ (OCR)
เมื่อลูกค้าแนบสลิป ระบบอ่านข้อความจากรูป/PDF ด้วย Google OCR (ภาษาไทย) แล้วตรวจ 5 อย่าง:
1. **เป็นสลิปโอนเงินจริงหรือไม่** (พบคำของสลิป เช่น โอนเงินสำเร็จ รหัสอ้างอิง ค่าธรรมเนียม พร้อมเพย์)
2. **ยอดเงินตรงกับออเดอร์หรือไม่** (รองรับ 1,245.00 / เลขไทย / 249,00)
3. **พบชื่อผู้รับ** ตามชื่อบัญชีใน `ACCOUNT_NAME`
4. **ไม่ซ้ำ** กับสลิปของออเดอร์อื่น (เทียบไฟล์ MD5 และรหัสอ้างอิงบนสลิป)
5. รูปถูกย่อเป็น JPEG ไม่เกิน 1600px ก่อนส่ง เพื่อให้ส่งไวและอ่านยอดแม่นขึ้น

| ผล | สิ่งที่เกิดขึ้น |
|---|---|
| **ผ่าน** | สถานะ → "รอตรวจสอบการชำระเงิน" ลูกค้าเห็น "ยอดตรงกับคำสั่งซื้อ" ครูกดยืนยันได้เร็ว (ป้ายเขียวในหลังบ้าน) |
| **ตรวจอัตโนมัติไม่ได้** (รูปไม่ชัด / อ่านยอดไม่ได้ / ไม่พบชื่อผู้รับ / OCR ใช้ไม่ได้) | รับสลิปไว้ ให้ครูตรวจเอง (ป้ายเหลือง) |
| **ยอดไม่ตรง / ไม่ใช่สลิป / ซ้ำ** | **ไม่รับสลิป** สถานะไม่เปลี่ยน ลูกค้าเห็นเหตุผล (เช่น "ยอดในสลิป 200.00 บาท ไม่ตรงกับ 498.00 บาท") พร้อมข้อความ **ให้โอนใหม่และแนบสลิปอีกครั้ง หรือโทรหาครูพิสมัย** (ปุ่มโทรในมือถือ) · ครูได้รับแจ้งเตือนพร้อมลิงก์สลิป (ป้ายแดง) |

- เบอร์ที่แจ้งลูกค้าตั้งที่ Script property `SLIP_CONTACT` (ค่าเริ่มต้น `ครูพิสมัย 093-586-9426`)
- ไฟล์สลิปที่ไม่ผ่านเก็บใน Drive ชื่อ `ไม่ผ่าน_…` เพื่อตรวจย้อนหลัง · สลิปที่ไม่ผ่านจะไม่ทับสลิปที่เคยรับไว้แล้ว · แนบได้ไม่เกิน 8 ครั้ง/30 นาทีต่อออเดอร์
- ตอน Admin กด "ชำระเงินแล้ว" ถ้าสลิปไม่ผ่านตรวจอัตโนมัติหรือไม่มีสลิป ระบบเตือนก่อนยืนยัน (ยืนยันเองได้เสมอ เช่น กรณีโอนสด/OCR อ่านผิด)
- ระบบ **ไม่อนุมัติอัตโนมัติ** ครูเป็นผู้กดยืนยันรับเงินเสมอ เพราะ OCR อ่านข้อความได้แต่พิสูจน์ไม่ได้ว่าสลิปเป็นของจริง (ยังต้องเทียบกับยอดเข้าบัญชี)
- **ตั้งค่าครั้งแรก:** `appsscript.json` เปิด Advanced Service "Drive API v3" และ scope `documents` ไว้แล้ว → วางไฟล์ใหม่ รันฟังก์ชันใดก็ได้ใน Apps Script 1 ครั้งเพื่อกดอนุญาตสิทธิ์ใหม่ แล้ว Deploy New version · ถ้า OCR ยังใช้ไม่ได้ (เช่น ยังไม่เปิด Drive API ในโปรเจกต์) ระบบจะรับสลิปให้ครูตรวจเองเหมือนเดิม ไม่ขัดข้อง
- ชีตออเดอร์เพิ่มคอลัมน์ AB–AE: ผลตรวจสลิป / ยอดที่อ่านได้ / หมายเหตุ / รหัสตรวจซ้ำ (เพิ่มให้อัตโนมัติ)

## ใบสั่งซื้อ / ใบเสร็จรับเงิน เป็นรูปภาพ JPG
- **สร้างที่หน้าเว็บ** ด้วย Canvas + ฟอนต์ Kanit (ขนาด A4 กว้าง 1240px ~250 KB/ใบ) จึงแสดงภาษาไทยและวันที่ พ.ศ. แบบเต็มได้คมชัดตรงกันทุกเครื่อง ไม่ต้องพึ่งฟอนต์ของ Google PDF
- **ใบสั่งซื้อ**: สร้างทันทีหลังกดสั่งซื้อ (มี QR พร้อมเพย์จาก `qr.jpg` ใน repo หรือรูปที่ Admin อัปโหลด + ยอดที่ต้องชำระ) → ดูตัวอย่าง/ดาวน์โหลด/แชร์ได้ และอัปโหลดเก็บใน Drive โฟลเดอร์ `ใบสั่งซื้อ (JPG)` อัตโนมัติ (ครั้งเดียวต่อออเดอร์ ไม่เขียนทับ)
- **ใบเสร็จรับเงิน**: ออกเมื่อ Admin ตรวจสลิปแล้วเปลี่ยนสถานะเป็น **ชำระเงินแล้ว** → ระบบออกเลข `RC2569-0001` (ครั้งเดียวต่อออเดอร์) แล้วสร้างรูป JPG บันทึกลง Drive โฟลเดอร์ `ใบเสร็จรับเงิน` และเก็บลิงก์ในชีตออเดอร์ (คอลัมน์ X)
  - ใบเสร็จมีจำนวนเงินตัวอักษร ช่องลงชื่อ และกรอบ "หลักฐานการรับเสื้อ"
  - เมื่อบันทึก **รับเสื้อแล้ว** (หรือยกเลิกการบันทึก) ระบบสร้างรูปใหม่อัตโนมัติ: ฉบับรับแล้วมีตราประทับ "รับเสื้อแล้ว" วันที่ และชื่อผู้รับ เก็บเป็นไฟล์ `RC…_รับเสื้อแล้ว.jpg` (ไฟล์เดิมไม่ถูกลบ)
  - Admin กดปุ่ม 🧾 ในแท็บออเดอร์เพื่อดู/ดาวน์โหลด/แชร์ได้ทุกเมื่อ · ลูกค้าค้นหาออเดอร์ที่ "ติดตามสถานะ" แล้วกด "ใบเสร็จรับเงิน (JPG)"
  - ข้อมูลในใบเสร็จมาจากเซิร์ฟเวอร์เสมอ (ลูกค้าสร้างรูปเองจากข้อมูลจริง) ส่วนไฟล์ใน Drive อัปโหลดได้เฉพาะ Admin (ต้องล็อกอิน) และตรวจว่าเป็นไฟล์ JPG ไม่เกิน 2 MB
  - ออเดอร์ที่ยังไม่ชำระ/ถูกยกเลิก จะขอใบเสร็จไม่ได้
- ไม่ต้องตั้ง `SITE_URL` อีกต่อไป (เลิกสร้าง PDF ฝั่งเซิร์ฟเวอร์ — รายงานสรุปของ Admin ยังเป็น PDF)
- รูปบนมือถือ iPhone: แตะค้างที่รูปแล้วเลือก "เพิ่มลงในรูปภาพ" หากปุ่มดาวน์โหลดไม่ทำงาน
- วันที่ทั้งระบบแสดงเป็น พ.ศ. แบบเต็ม เช่น `3 ตุลาคม 2569 14:05 น.`

## สถานะ "รับเสื้อแล้ว" (กันรับซ้ำ / หลักฐานส่งมอบ)
- ออเดอร์ที่ **ชำระเงินแล้ว** จะมีปุ่ม 📦 **บันทึกรับเสื้อ** ในแท็บออเดอร์ → กรอก ชื่อผู้รับ · วัน-เวลาที่รับ (ค่าเริ่มต้นคือปัจจุบัน แก้ย้อนหลังได้ แต่ห้ามเป็นอนาคต) · หมายเหตุ (เช่น ผู้รับแทน / เลขพัสดุ)
- บันทึกได้ครั้งเดียวต่อออเดอร์ ถ้ามีคนมารับซ้ำระบบแจ้งว่ารับไปแล้วเมื่อไหร่/โดยใคร · ออเดอร์ที่ส่งไปรษณีย์จะใช้คำว่า "จัดส่งแล้ว"
- เก็บในชีตออเดอร์ คอลัมน์ Y–AA (วันที่รับเสื้อ / ผู้รับเสื้อ / หมายเหตุ) และบันทึกประวัติลงคอลัมน์ "อัปเดตสถานะล่าสุด"
- ใบเสร็จที่ดาวน์โหลดหลังบันทึก จะแสดงข้อความ "รับเสื้อแล้ว เมื่อ … ผู้รับ …" · ลูกค้าเห็นสถานะเดียวกันที่หัวข้อ "ติดตามสถานะ"
- ออเดอร์ที่บันทึกรับแล้ว: ลบไม่ได้ และเปลี่ยนสถานะชำระเงินไม่ได้ ต้องกด "ยกเลิกการบันทึก" ก่อน (ใช้เมื่อบันทึกผิด)
- มีตัวกรอง "รับเสื้อ: รอรับ / รับแล้ว", การ์ดสรุป "รอรับเสื้อ / รับเสื้อแล้ว (ตัว)", รายงาน PDF และ CSV มีข้อมูลการรับเสื้อ

## รอบการสั่งจอง (หลายรอบ)
Admin กำหนดที่หลังบ้าน → แท็บ **รอบสั่งจอง** (หรือแก้ตรง ๆ ในชีต `รอบสั่งจอง`)
- แต่ละรอบมี: ชื่อรอบ · วัน-เวลาเริ่มรับ · วัน-เวลาปิดรับ · **จำกัดจำนวนเสื้อรวมทุกไซส์** (0 = ไม่จำกัด) · เปิดใช้งาน
- ลูกค้าสั่งได้เฉพาะรอบที่ "กำลังเปิดรับ"; ออเดอร์จะถูกบันทึกเข้ารอบนั้นอัตโนมัติ (คอลัมน์ รหัสรอบ/ชื่อรอบ)
- เมื่อยอดรวมถึงที่จำกัด รอบจะ "เต็ม" ทันที; ถ้ายกเลิกออเดอร์ ระบบคืนโควต้าให้รอบอัตโนมัติ
- รอบที่เปิดใช้งานห้ามมีช่วงเวลาซ้อนกัน (ระบบตรวจตอนบันทึก)
- โควต้ารายไซส์ (แท็บไซส์/ราคา/โควต้า) ยังใช้ร่วมได้ และสวิตช์หลักใช้ปิดรับทุกรอบฉุกเฉิน
- เวลาอ้างอิงเขตเวลา Asia/Bangkok · รายงานและ CSV แยกตามรอบ
- **อัปเกรดจากเวอร์ชันเก่า:** วาง Code.gs ใหม่ → Deploy New version → เรียกหน้าเว็บ 1 ครั้ง ระบบสร้างชีตรอบ (มี "รอบที่ 1" 30 วัน) และเพิ่มคอลัมน์ในชีตออเดอร์ให้เอง ออเดอร์เก่าจะแสดงเป็น "ไม่ระบุรอบ"

## หมายเหตุ
- **ทุกครั้งที่แก้ `Code.gs` ต้อง Deploy → Manage deployments → Edit → New version** (URL เดิมใช้ต่อได้)
- API เรียกได้เฉพาะฟังก์ชันใน whitelist `API`; คำสั่ง `admin*` ต้องมี token จาก `adminLogin` (ล็อก 10 นาทีเมื่อใส่รหัสผิด 5 ครั้ง)
- ใช้ `Content-Type: text/plain` ตอน fetch เพื่อเลี่ยง CORS preflight ที่ Apps Script ไม่รองรับ
- รูปสลิป/ใบสั่งซื้อ PDF/รายงาน เก็บใน Drive โฟลเดอร์ `ระบบเสื้อที่ระลึก ผ้าป่าศิษย์เก่า 2569/`
- อย่า commit `.clasp.json` ถ้า repo เป็น public
